# Codex adapter handoff

**Later integration evidence:** this file records the initial adapter handoff. The subsequent [investigator runtime proof](investigator-runtime-proof.md) passed the image transport → four dynamic tools → actual ngspice → validated answer path in 49.64 seconds. Its input was a controlled historical practice screenshot, not a physical circuit photograph. The later production runtime uses dynamic-only tools and a restricted child environment; the initial untested-image statements below are historical. Milestone 2 remains unchecked because the complete acceptance boundary is broader than this software proof. The afternoon cancellation follow-up also bounds preflight within the total request deadline and closes the child when cancelled; 25 offline runtime checks passed.

Status: **narrow subscription tool loop proven; milestone 2 is not accepted**. The installed CLI is `codex-cli 0.155.0-alpha.16.4`. Three explicitly authorized live model turns were made; no paid API request, physical measurement, or hardware action was made.

## Implemented

- `services/bench/src/ohmpath/ai/codex.py`: bounded JSON-lines supervisor, pinned CLI check, read-only ChatGPT account/model/allowance inspection, explicit Astra/medium/standard-speed selection, model fallback disabled, one active turn, interruption, event limits, tool/action denial, and locally checked revision/evidence references in final JSON output. The concrete process launcher is **read-only inspection only** and refuses live turns because its inherited Codex home/configuration has not been isolated.
- `services/bench/src/ohmpath/ai/bridge.py`: four exact MCP tool names (`get_session_evidence`, `get_circuit_graph`, `simulate_variant`, `propose_test`), strict arguments, result size and revision checks, and explicit denial of confirmation/device/other methods. A stdio MCP entrypoint uses only a fixed `127.0.0.1` bench URL and an ephemeral model capability from environment variables; it never accepts an arbitrary URL or token on command arguments.
- `services/bench/tests/test_ai_codex.py`: offline replay for tool denial, stale/unlinked results, subscription/model/allowance preflight, rerouting, cancellation, stale/malformed/overlong output, disallowed actions and approvals, allowed versus foreign MCP tool events, the experimental dynamic-tool fallback, and fixed model-only HTTP route mapping. One test runs real ngspice through the model-only route and then records a proposed test using its simulation evidence ID.
- `services/bench/src/ohmpath/ai/live_proof.py`: one-shot development proof harness guarded by an explicit `--authorized-live-proof` flag. It starts a synthetic divider session, checks separate capabilities, applies strict app-server overrides to the existing signed-in home, checks the effective config/model/allowance, and attempts one bounded turn. It has no reset or paid API fallback. The latest successful mode uses `thread/start.dynamicTools`, with three model tool calls dispatched through the same local bridge.
- `services/bench/src/ohmpath/ai/runtime.py`: callable `run_investigation(base_url, model_token, sid, circuit_revision, question, image_path=None, cancel_event=None)`. It uses the same signed-in subscription and checked strict config, rechecks a 10% allowance margin, pins Astra/medium/default tier, starts an ephemeral read-only thread in a temporary cwd, advertises only the four dynamic tools, validates current revision and simulation/proposal evidence, and closes the process on completion or failure. `image_path` accepts only a reviewed local PNG/JPEG of at most 2 MB; no image turn has yet been tested live. Cancellation is checked during the bounded event loop. The root service must run it in a supervised worker, pass only a model-only capability, and expose status/cancel; this module does not start work itself.

## Remaining gate

The default `JsonLineProcess` inherits the user's Codex home and intentionally raises `live_process_isolation_unverified` for any live turn. The explicit proof harness and new runtime helper instead construct checked `--strict-config` overrides while keeping ChatGPT sign-in. Preflight confirms effective configuration and narrow capability denials, and the dynamic-tool model loop passed on the synthetic fixture. This is **not** an OS-level sandbox proof against arbitrary process file access, nor a live image or long-running application test. Root should review the isolation boundary before exposing the helper in the UI. App-server has separate host RPCs such as `thread/shellCommand` that a client must never expose to the model or renderer.

The coordinator owns the bench API and shared contracts. The agreed model routes are now implemented: `POST /v1/model/sessions/{sid}/simulate` (reviewed variant only) and `POST /v1/model/sessions/{sid}/proposals` (proposal only, never a user measurement request); separate user confirmation endpoints are denied. The bridge expects simulation success to include `session_id`, `circuit_revision`, `status: completed`, `simulation_id`, `input_hash`, and `evidence_ids`; a proposal response includes `status: proposed`, `proposal_id`, and unchanged evidence IDs. The **image → model** acceptance path remains untested; this proof used text and a synthetic fixture. The coordinator must review and provide any further live authorization. Do not mark milestone 2 complete from this narrow proof.
