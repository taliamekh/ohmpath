# Optional ElevenLabs playback implementation

This is an implementation handoff, **not a claim that speech playback works on a speaker**. The worker used only offline checks. The coordinator subsequently verified one authorized 63-character synthesis stream (162,726 PCM bytes, 36 chunks), without playback or retained audio. See the [current progress log](software-finish-progress.md) for the credit reservation and interface checks. Exact character voice matching remains unresolved.

## Main-process contract

`createElevenLabsConnection({ safeStorage, filePath, fetchImpl, onSpeechEvent })` retains the existing encrypted credential and read-only metadata actions. The callback receives only `{type, request_id, ...}` presentation events; it never receives the key, text, provider response body, account information, or an opaque provider ID. It must be forwarded only to the trusted main renderer, never the companion.

Every launch starts with generation off, even when a credential and voice were saved. A deliberate user control may call `handle('setGenerationEnabled', {enabled: true, characterBudget: 100})`, where the per-launch budget is a positive integer at most 1,000 text characters. `handle('setGenerationEnabled', {enabled: false})` immediately aborts active work. Re-enabling cannot replenish a budget spent earlier in the same process. Status adds `generation_enabled`, `remaining_session_characters`, `reserved_session_credits`, `provider_remaining_credits`, `speaking_request_id`, and safe `last_error`. The existing metadata/link fields retain their meaning. `generation_tested` remains false until the coordinator records an actual playback test.

Only an explicit approved-text action may call `handle('speak', {request_id: '<UUID>', text: '...'} )`. The text is nonblank, contains no control characters except ordinary whitespace, and is at most 1,000 UTF-16 units. A successful preflight returns `{accepted: true, request_id, reserved_credits, remaining_session_characters}` promptly; the stream continues in the background. The caller should show the text as a subtitle immediately and use playback callbacks to mark actual speaking, rather than treating acceptance or provider stream start as audible output.

Before each POST the adapter rereads fresh `/v1/user/subscription`, `/v2/voices`, and `/v1/models` metadata. It requires zero overage extension, reported allowance, the saved voice still in the list with `premade`, `generated` or `cloned` category, and the exact `eleven_flash_v2_5` model with TTS capability, a stated maximum request length and a stated character-cost multiplier. Generated and instant-cloned voices are account-local voice choices; their content and required permissions are handled separately during creation. Professional, shared and unknown categories remain excluded, including after a previously valid saved voice changes category. Settings presents only eligible choices. It does not choose a fallback model or a shared voice with an unknown custom rate. A reservation is `ceil(text.length × max(1, model character_cost_multiplier))` credits. This is intentionally conservative, not an assertion that credits equal characters: ElevenLabs says Flash may cost less and some shared voices cost more. The local character limit and the account's remaining reported credits are separate gates. Any request that may have reached synthesis keeps its full local reservation even after cancel or error; there is no automatic retry, refund assumption, top-up, or reset.

The single outbound synthesis endpoint is `POST https://api.elevenlabs.io/v1/text-to-speech/{selected_voice_id}/stream?output_format=pcm_24000` with `model_id: eleven_flash_v2_5`. Redirects and unexpected response formats are rejected. The stream has a 90-second timeout and an 8 MiB byte ceiling. Audio events are aligned 16-bit little-endian PCM chunks of at most 48 KiB, base64 encoded for the trusted renderer:

```json
{"type":"start","request_id":"<UUID>","sample_rate":24000,"format":"pcm_s16le"}
{"type":"chunk","request_id":"<UUID>","sample_rate":24000,"pcm_base64":"<bounded PCM>"}
{"type":"end","request_id":"<UUID>"}
```

Errors use `{type:'error', request_id, error:'safe_code'}` and cancellation uses `{type:'cancelled', request_id}`. `handle('cancelSpeech', {request_id})` aborts a matching active request or invalidates its pending metadata preflight before synthesis; omit the ID to cancel the current request and invalidate queued speech work. Disabling, changing the voice, relinking, or disconnecting does the same. A late chunk is ignored after cancellation. Each request ID must be new; the coordinator should also cancel on session/revision changes and when the user interrupts or navigates away.

## Renderer handoff

### Current live conversation behavior (September 27, 2026)

The Live help microphone no longer depends on an active measurement session. **Talk to helper → Finish and open Photo help** captures at most 20 seconds locally, releases the microphone, transcribes, then imports a fresh overview frame and carries the question into the standalone Photo help draft for explicit review and submission. That frame replaces the previous spoken question's image context. Navigation invalidates a late capture or response. Photo help's separate recording button still fills an editable draft.

With a voice enabled and **Read replies aloud** checked, a completed answer is spoken once. A bounded summary uses complete paragraphs/sentences below the existing 1,000-character request ceiling; full explanations and suggested checks stay visible. The control can be unchecked, and Stop speaking remains available. Local system speech supports general explanations without an active measurement session. No speech confirms a reading or starts motion. This supersedes the earlier draft-only and Listen-only renderer notes below, without changing the synthesis provider or spending limits.

`SpeechPlayback.prepare()` resumes the output context during the user's Ask/Record gesture; the later reply reuses it. The synthetic Electron test covers no-session recording, cancellation, fresh Pi snapshot binding, one reasoning submission, automatic reply speech, stopped microphone tracks, and explicit playback cancellation. Camera lifecycle and diagnosis-to-turret handoff tests also pass. These are software tests; they do not verify a person's microphone input, audible output, or physical laser alignment.

The launch budget now caps both text characters and conservatively reserved credits to the configured value (maximum 1,000 of each). A higher model rate cannot exceed the credit ceiling. A request ID that may already have been charged is rejected on reuse. Request-local delivery settings use speed 0.95, stability 0.7, similarity 0.75, style 0 and no speaker boost; these shape the selected stock voice rather than claiming an exact anime voice.

`new SpeechPlayback(onPlaybackState)` accepts the forwarded events. Its `arm(requestId)` **must run synchronously in an explicit click or key gesture**, before the asynchronous `speak` IPC, so a browser audio context is never started by background text. Call `receive(event)` for provider events. Its callback reports `started` only after the first audio buffer is scheduled in a running context; `ended` follows buffer drain or local stop; `error` marks format/context/resource failure. The coordinator should cancel the provider request on playback error. `stop(requestId?)` immediately clears scheduled buffers and the receive queue, and `dispose()` also closes the context. The player accepts only 24 kHz signed PCM, at most 48 KiB per chunk and 8 MiB total. Fast HTTP delivery can fill its bounded receive queue while the scheduler holds at most eight audio nodes and roughly three seconds ahead; valid audio is not discarded simply because it arrived faster than playback. It never uses browser speech synthesis or another provider as fallback. The UI must keep text/subtitles available when speech is off or fails.

`SpokenQuestion` is a separate local transcription control for Photo help. Its Start action checks local speech status, calls `enableMicrophone`, and requests audio input; Finish turns up to 20 seconds of in-memory capture into mono 16 kHz PCM16 WAV and calls `photoTranscribe`. At the 20-second limit it releases the microphone and waits for Finish before sending. A valid local transcript goes only to `onText` so the user can review the draft and explicitly ask about their images. Cancel, leaving the page, or disabling the component stops tracks, closes the audio context, drops captured data, and calls `disableMicrophone`. No spoken candidate is submitted as a question or confirmed measurement automatically. This path has only static verification by this worker, not a microphone or recognition test.

The coordinator owns the main/preload/Settings/Photo help wiring and any global user-authorized spending cap. The account's per-key cap is independent of the subscription metadata endpoint; this adapter cannot inspect or increase it. Check live subscription usage and the configured key cap before any authorized real test, and compare usage after it. The existing key may be capped below the user's broader 10,000-credit authorization.
